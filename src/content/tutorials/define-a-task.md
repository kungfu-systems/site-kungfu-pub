## 从“帮我整理一下”开始

“帮我整理一下资料”表达了愿望，但没有说明整理哪些资料、按什么方式整理、缺少信息时怎么办。执行者很容易做出一个看起来完整、却不符合预期的结果。

可以先写出一个最小任务说明，让人和 Agent 都能理解。

## 四格任务说明

| 部分 | 需要回答的问题     | 资料整理示例                             |
| ---- | ------------------ | ---------------------------------------- |
| 目标 | 最后交付什么？     | 一份带来源链接的阅读清单                 |
| 输入 | 可以使用哪些材料？ | 指定文件夹中的三份公开文档               |
| 边界 | 哪些动作被允许？   | 只读原文件，另存结果，不修改来源         |
| 验收 | 怎么检查结果？     | 每条记录能回到来源，无法读取的文件有说明 |

验收标准尽量描述可观察的结果。比如“每条记录有来源”可以检查；“整理得非常专业”仍需要进一步解释。

## 给失败留下位置

资料可能缺标题，网页可能打不开，输入可能互相矛盾。这些情况应该进入任务设计。

- **缺信息**：标记未知，不把猜测写成事实。
- **工具失败**：记录失败原因，在有界重试之后停止或交还。
- **来源矛盾**：并列保留不同说法及各自来源。
- **超出范围**：停在当前边界，说明还需要什么。

任务说明不需要预测所有问题，但要让失败能够被看见。

## 把验收写成样例

```text
成功样例：三份资料都可读取，输出三条带有效来源的记录。
失败样例 A：其中一份不可读取，输出两条记录和一条失败说明。
失败样例 B：一份资料没有标题，保留来源并将标题标记为未知。
```

检查实际结果时，既看输出格式，也看内容是否忠于输入。格式正确的表格也可能包含编造的字段。

## 你的练习

选择一项日常工作，例如生成会议摘要、比较两份说明或整理公开资料，写出一份四格任务说明。

再增加一个成功样例和两个失败样例。请另一位读者只看这份说明，判断他是否知道怎样验收。

**完成标准：** 任务说明包含目标、输入、动作边界和可检查的结果；出现缺失信息时仍有明确处理方式。
